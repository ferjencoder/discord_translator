Failure modes:
- original: post the original source text without the noisy failure banner
- skip: do not post a destination copy when translation fails
- marked: preserve the old [Translation unavailable ...] banner

Status command:
- /translator-status
- ephemeral
- allowed for Administrator / Manage Server / configured leadership role names
- tracks success rate, 429s, timeouts, character volume, queues, cooldown and estimated Cloud cost

Important: telemetry is stored in STATE_DB. If the Render filesystem is ephemeral, metrics reset when that filesystem is replaced.

Rate-limit behavior in this build:
- every Google HTTP call, including fallback, passes through the same global start gate
- TranslationNotFound / endpoint-parser failures wait before JSON fallback
- HTTP 429 pauses all pending destination starts for the full cooldown
- a 429 retry does not also use the old 1-10 second exponential backoff
- the endpoint that returned 429 is retried after cooldown; it is not immediately bypassed

Discord webhook behavior in this build:
- a normal 429 respects Discord's Retry-After but never waits longer than WEBHOOK_MAX_RETRY_AFTER_SECONDS
- a Retry-After above that cap is treated as pathological; only that destination webhook is quarantined and the other language webhooks continue
- webhook.send itself is bounded by WEBHOOK_SEND_TIMEOUT_SECONDS
- each destination delivery is bounded by WEBHOOK_DELIVERY_TIMEOUT_SECONDS
- no Discord 429 can set the shared webhook gate to an hours-long delay
